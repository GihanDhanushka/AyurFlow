# Shared API and security contract — review draft

**Task:** TASK-SET-04 (Member A; all module owners review). **Status:** proposed, not team-approved. **Source:** AyurFlow SRS v1.0 §§3.2–3.3, 4, 13, 15 and DEC07; team task plan p. 3. This document is the concrete contract for review. It does not declare protected endpoints implemented or close DEC07. The implemented API remains documented in [openapi.yaml](openapi.yaml).

## Rules already required by the SRS

- Go/Gin is the authoritative REST API at `/api/v1`; Next.js calls it through the same-origin rewrite and never connects to PostgreSQL. Backend validation, authorization and transactions are mandatory even when the browser validates input.
- Stored record IDs are server-generated. Every protected read, mutation, report and export checks both role and record access. Administrator alone cannot read clinical notes. Do not expose a protected resource route until these checks and CSRF are in place.
- Use opaque server-side sessions with Secure, HttpOnly and SameSite cookies. State-changing cookie-authenticated requests require CSRF protection; logout, expiry, revocation and login throttling are required. DEC07 must set the policy values and recovery flow.
- Persist instants in UTC and render them in Asia/Colombo. Send money as integer LKR minor units. Send quantities as fixed-precision decimal grams, never binary floating-point values. DEC03 still sets the gram scale and rounding rule; DEC04 sets billing rounding/examples. Date-only expiry stays a date.
- A consumption or receipt submission has an operation identifier unique within its action type. An identical successful retry returns the original result; the same identifier with changed content conflicts. After a network timeout, the client must retry or retrieve that operation rather than assume failure.
- The backend returns 400 for malformed requests, 401 for unauthenticated requests, 403 for forbidden actions, 404 for absent or deliberately hidden resources, 409 for state/concurrency conflicts and 422 for valid JSON with invalid field values. Errors must be useful without exposing another patient's data or internal stacks.

## Proposed wire conventions for team review

| Topic | Candidate convention | Review owner / gate |
| --- | --- | --- |
| IDs | UUID strings for stored IDs, generated by the server. Clients never choose a patient, invoice, session or audit ID. A client generates a fresh UUID `operationId` only for each intended consumption/receipt action. | A with B–E, Sprint 1 |
| Paths | Plural resource names under `/api/v1` (`/patients`, `/sessions`, `/invoices`). Use `POST /{resource}/{id}/{action}` for guarded transitions such as `sign`, `approve`, `start`, `confirm-consumption` and `issue`. Do not infer that any example path is implemented. | A with each owner, TASK-SET-06 |
| Mutation methods | `POST` creates/acts; `PATCH` changes an editable draft; `GET` reads. A confirmed/signed/issued record has no ordinary edit or delete route. Rejected transitions leave prior state intact. | A with each owner |
| JSON names | Lower camel case in requests/responses (`patientId`, `occurredAt`, `amountMinor`, `quantityGrams`, `operationId`). Backend database names may remain snake case. | A with F/B–E |
| UTC instants | RFC 3339 strings with UTC `Z`, such as `2026-10-19T08:30:00Z`. Date-only fields use `YYYY-MM-DD` without a timezone. Frontend displays instants in Asia/Colombo. | A with F/D |
| Money/grams | `amountMinor` is a JSON integer; `quantityGrams` is a decimal **string**, such as `"50"`. No JSON float for stock or money. Exact gram scale/rounding and line rounding remain DEC03/04. | A with D/E; DEC03/04 |
| Lists | Default `limit=25`, maximum `limit=100`, optional opaque `cursor`; return `items` and `nextCursor` (`null` at end). Each owner chooses a documented stable indexed sort with ID as tie-breaker and applies permissions before returning rows. | A with B–F |
| Errors | Preserve the existing `{ "error": { "code", "message" } }` envelope. For 422 only, optionally include `fieldErrors` keyed by request field; never echo clinical text, secrets or inaccessible IDs. Use stable machine codes and plain user-facing messages. | A with F/B–E; DEC07 |
| Idempotency | Put `operationId` in the JSON body of consumption and receipt actions. Uniqueness is `(action type, operationId)` in PostgreSQL. Store a fingerprint of validated material fields and the successful outcome in the same transaction as the business/audit write. An identical retry returns the original status/body; changed content returns 409. Serialize parallel attempts. | A with D/E; DEC07 |

Examples below illustrate the proposed shape; no example endpoint is currently registered.

### Paginated read

```http
GET /api/v1/patients?limit=25&cursor=opaque-value
Accept: application/json
```

```json
{"items":[{"id":"6a53df36-39ca-4c55-b953-646b97ed4a4d","displayName":"Synthetic Patient"}],"nextCursor":null}
```

The response includes only fields permitted to that role and record. A requester without record access does not gain it by guessing a URL or cursor.

### Error examples

```json
{"error":{"code":"validation_failed","message":"Check the highlighted fields.","fieldErrors":{"amountMinor":"Enter a positive amount."}}}
```

This would be HTTP 422. A stale transition or changed operation retry would be HTTP 409, for example:

```json
{"error":{"code":"conflict","message":"This action conflicts with the current record state."}}
```

Invalid credentials use one generic message whether the login identifier exists or not. For an inaccessible patient record, return 404 when revealing its existence would expose protected information; 403 remains appropriate for a known action the role cannot perform. Actual error-code names must be checked against the existing `not_found`, `not_ready` and `internal_error` codes before handlers are added.

### Consumption/receipt retry example

```json
{"operationId":"c990f6c9-d871-45ca-a4fc-16b25e09d4a7","amountMinor":125000,"method":"cash"}
```

This is an illustrative receipt action body, not the full billing schema. The client keeps this `operationId` when retrying the **same** intended posting after an unknown outcome. A new posting gets a new ID. The server validates the invoice and balance in its transaction, writes the receipt and audit event, and durably records the operation result. D applies the same rule to actual consumption with its own payload fields.

## DEC07 decisions to record before auth routes ship

The values below are **candidates for team review**, not configured application behavior or clinic approval.

| Question | Candidate | Required review/verification |
| --- | --- | --- |
| Idle and absolute session expiry | 30 minutes of inactivity and 8 hours from login; expiry uses server time and revokes action immediately. | A/team select values; AT01 tests both boundaries. |
| Failed-login throttling | At most 5 failed attempts per login identifier and source within 15 minutes, followed by a 15-minute delay; use generic responses and do not expose whether an account exists. | A/team assess shared terminals, NAT and denial-of-service tradeoffs; AT01 tests limits. |
| Recovery | Administrator starts a one-use, short-lived password reset delivered outside the app; reset revokes active sessions and forces a password change. No public self-service signup or email integration. | A/team agree operator, delivery and expiry before implementation. |
| Session cookie | `__Host-ayurflow_session`, `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`, no `Domain`; production over HTTPS. Session token is random and stored only as a hash server-side. | A/F verify browser/proxy behavior and local development setup. |
| CSRF and login | Authenticated unsafe methods require `X-CSRF-Token` matching the server session, plus same-origin `Origin` checks. Login is checked for same-origin `Origin`; a successful login rotates the session and returns a CSRF token to the same-origin frontend. | A/F review bootstrap/refresh/logout flow and direct-request tests. |
| Auth action shape | Candidate routes: `POST /auth/login`, `POST /auth/logout`, `GET /auth/session`. Session response contains minimum identity/roles and a CSRF token for the same-origin UI; `Cache-Control: no-store`. | A/F review response fields, status codes and OpenAPI before registration. |
| Retry/error conventions | Use the wire and idempotency rules above; agree action route names, operation field, stable code names and whether validation errors use `fieldErrors`. | A, D, E and F review examples; AT10/AT12 verify retries. |
